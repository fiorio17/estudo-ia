Aula 12O que é PLN

Processamento de Linguagem Natural (PLN/NLP) é a área da IA que permite aos computadores processar, analisar, interpretar e gerar linguagem humana, em texto ou fala: conversas, mensagens, documentos, comandos de voz. Tarefas típicas: detectar spam, resumir um documento longo, gerar respostas a partir de uma pergunta.

Por que a linguagem é difícil para o computador

Computadores vão bem com dados estruturados (números, tabelas). A linguagem humana traz:

DesafioExemploProblema
Ambiguidade"banco": instituição financeira ou assentoO significado depende do contexto
Ironia e sarcasmo"Nossa, que ótimo! Perdi todos os meus arquivos."Palavras positivas, intenção negativa
Variações"Blz, vlw! Kkk 😅"Gírias, abreviações, erros e emojis também carregam significado

Não limpe tudo

Remover tudo indiscriminadamente é um erro. A palavra "não" pode inverter o sentido da frase; emojis, pontuação e maiúsculas podem carregar sentimento. Em tokenização simples, tokens = palavras, mas modelos modernos dividem palavras em partes menores.

Aula 12 · laboratórioStopwords, stemming e lematização

  • Stopwords: palavras muito frequentes (artigos o, a, um; preposições de, em, para, com; conjunções e, ou, mas; pronomes ele, ela, nós) que, em certas tarefas, contribuem pouco. Mas uma stopword nem sempre é irrelevante: "Eu não gostei do filme".
  • Stemming: corta prefixos/sufixos por regras. O resultado (stem/radical) nem sempre é uma palavra válida: estudando, estudaram, estudante → estud. Rápido e simples, mas pode agrupar palavras de sentidos diferentes.
  • Lematização: leva a palavra à forma canônica (lema), considerando a gramática: gatos → gato, estudando → estudar, melhores → bom, "são" → ser ou são, conforme o contexto. Exige mais recursos linguísticos, mas é mais interpretável.

Aula 12 · laboratórioBag of Words e TF-IDF

Bag of Words (saco de palavras)

Reúne os textos, cria um vocabulário, conta a frequência de cada palavra em cada texto e representa cada texto por um vetor. Exemplo: "gosto de Python" e "gosto de Java" com vocabulário [gosto, de, Python, Java] dão [1,1,1,0] e [1,1,0,1]. É simples e bom como ponto de partida, mas ignora a ordem e o significado.

TF-IDF

Dá peso às palavras pela frequência no documento e pela raridade no corpus.

TF(t,d) = (vezes que t aparece em d) / (nº de palavras de d)
IDF(t) = log₁₀( N / df(t) )   (N = nº de documentos, df = docs que contêm t)
TF-IDF(t,d) = TF(t,d) × IDF(t)

Palavra em quase todos os textos ("que", "para") → IDF perto de 0. Palavra rara ("criptografia") → IDF alto. TF alto + IDF baixo → peso baixo; TF alto + IDF alto → ótima "assinatura" do texto. Um corpus é o conjunto de documentos.

Calculadora (um documento por linha)

Conferindo o slide

Doc 1 = "A inteligência artificial aprende." (4 palavras). "aprende": TF = 1/4 = 0,25; IDF = log₁₀(2/2) = 0; TF-IDF = 0. "inteligência": TF = 0,25; IDF = log₁₀(2/1) = 0,301; TF-IDF = 0,075. A palavra "a" também aparece nos dois documentos, por isso também zera.

Observação

Bibliotecas como o scikit-learn usam variações (logaritmo natural, suavização, normalização), então os números diferem dos do slide. Em prova, use a fórmula da aula. Palavra rara não é, por si só, importante: o peso depende da frequência e da distribuição.

PLN IILimites do BoW e do TF-IDF

Representar o texto só pela ocorrência ou importância estatística das palavras não captura o significado. Três limitações:

Ignora a ordem"O cachorro mordeu o homem" × "O homem mordeu o cachorro"Mesmo vetor, significados diferentes

Aula 12 + PLN IIEmbeddings

Embeddings são representações numéricas de palavras, frases ou outros elementos como vetores num espaço multidimensional, aprendidos a partir de dados, capazes de capturar relações semânticas (e, conforme o método, sintáticas). A imagem do slide: um GPS do significado — palavras de sentido parecido ficam "vizinhas" no mapa.

PalavraDim 1Dim 2Dim 3
carro0,820,710,15
automóvel0,790,740,18
banana0,120,210,91

Carro e automóvel têm vetores parecidos; banana é diferente. Embeddings reais não têm dimensões interpretáveis como "animal" ou "voador": o significado emerge do vetor como um todo (50, 100, 300, 768, 1536 dimensões...).

Como uma palavra vira vetor

No Word2Vec, uma rede neural é treinada para prever uma palavra a partir das palavras ao redor. Nos textos "o cachorro brinca no parque / o gato brinca no parque / o cachorro corre no jardim / ...", cachorro e gato aparecem em contextos parecidos, então ganham vetores parecidos.

Detalhe cobrado

Os vetores não são calculados contando quantas vezes as palavras aparecem juntas. São parâmetros aprendidos durante o treinamento.

Estático × contextualizado

EstáticosContextualizados
ExemplosWord2Vec, GloVeTransformers, como o BERT
RepresentaçãoEm geral, um vetor por palavraPode variar conforme o contexto
Diferencia sentidosNão diretamente ("banco" tem o mesmo vetor nas duas frases)Sim, em geral
UsoSimilaridade entre palavras, recursos para modelosCompreensão contextual, classificação, extração de informação

Aplicações

  • Busca semântica: "como limpar o sofá" encontra "Técnicas de higienização de estofados", sem nenhuma palavra em comum, porque a pergunta inteira vira um vetor e se procuram páginas com vetores próximos.
  • Recomendação, classificação de textos, análise de sentimentos.

PLN II · laboratórioComparando vetores: similaridade de cosseno

cos(A,B) = (A · B) / (‖A‖ · ‖B‖)

A · B é o produto escalar (soma dos produtos componente a componente) e ‖A‖ é a norma (comprimento) do vetor. O cosseno compara a orientação, não o tamanho. Próximo de 1: mesma direção; próximo de 0: vetores ortogonais, sem relação; próximo de −1: direções opostas.

PLN II · PythonExplorando embeddings com Word2Vec (gensim)

# pip install gensim
from gensim.models import Word2Vec

frases = [
    ["o","cachorro","corre","no","parque"],  ["o","gato","corre","no","jardim"],
    ["o","cachorro","brinca","no","jardim"], ["o","gato","brinca","no","parque"],
    ["o","carro","anda","na","estrada"],     ["o","ônibus","anda","na","rodovia"],
    ["o","carro","é","um","veículo"],        ["o","ônibus","é","um","veículo"],
]

modelo = Word2Vec(
    sentences=frases,   # lista de frases (cada frase = lista de tokens)
    vector_size=20,     # dimensionalidade do vetor de cada palavra
    window=3,           # 3 palavras antes e 3 depois do termo alvo
    min_count=1,        # ignora palavras com menos aparições que isso
    workers=1,          # threads de treinamento
    seed=42             # semente: resultados reprodutíveis
)

modelo.wv["cachorro"]                         # vetor aprendido
modelo.wv.similarity("cachorro", "gato")      # similaridade de cosseno
modelo.wv.most_similar("cachorro", topn=3)    # vizinhos mais próximos

PLN IITransformers

TécnicaO que fazPrincipal limitação
Bag of WordsRepresenta palavras por suas ocorrênciasNão representa bem ordem nem significado
TF-IDFPesa palavras pela importância nos documentosNão compreende o contexto semântico

Em "O banco estava cheio de pessoas" × "O banco estava cheio de dinheiro", BoW/TF-IDF não resolvem a ambiguidade e um embedding estático pode dar vetor semelhante ao "banco" nos dois casos; um modelo com representações contextuais produz representações diferentes conforme as outras palavras.

Um Transformer é uma arquitetura de rede neural para processar sequências (especialmente texto), que ganhou destaque pelo mecanismo de atenção. Foi apresentada no artigo Attention Is All You Need (2017) e é a base de muitos LLMs.

Fluxo conceitual

Texto → Tokenização → Representações numéricas → Atenção → Processamento neural → Saída

Tokens não são necessariamente palavras inteiras: podem ser parte de uma palavra, pontuação ou outro fragmento.

PLN II · laboratórioMecanismo de atenção

Em "O animal não atravessou a rua porque ele estava cansado", para interpretar "ele" é preciso ligá-lo a "animal". A self-attention deixa cada token olhar para todos os outros da sequência e atribuir pesos diferentes. Os pesos vêm das representações aprendidas, não de regras gramaticais programadas.

Query, Key e Value

ElementoIntuiçãoFunção
Query (Q)O que estou procurando?O que o token quer identificar nos demais
Key (K)O que posso oferecer?Características para calcular a compatibilidade com uma Query
Value (V)Qual informação carrego?A informação que será combinada com a dos outros tokens

Analogia da biblioteca (só ilustrativa): Query = a pergunta ao bibliotecário; Key = as informações que identificam cada livro; Value = o conteúdo do livro. Na prática, Q, K e V são vetores numéricos aprendidos, obtidos por três transformações do embedding de entrada: Q = X·WQ, K = X·WK, V = X·WV, com matrizes de pesos aprendidas no treino.

Atenção(Q,K,V) = softmax( Q·Kᵀ / √dk ) · V
  1. Compatibilidade: produto escalar entre a Query do token e a Key de cada token.
  2. Escala e softmax: divide por √dk (dk = dimensão das Keys) e aplica softmax, que transforma os valores em pesos que somam 1.
  3. Combinação: soma dos vetores Value ponderada pelos pesos, z = Σ pesoᵢ · Vᵢ.
  4. Resultado: uma representação nova, contextualizada, do token.

Atenção do token "ele"

Compatibilidades do slide (valores ilustrativos): O 0,2 · animal 2,8 · atravessou 0,5 · rua 0,7 · cansado 1,9. Edite as compatibilidades, os Values (2 dimensões, fictícios) e dk.

dk (dimensão das Keys)

Leitura correta do peso: 55 % de atenção em "animal" não significa 55 % de certeza de que "ele" = "animal". Significa que o Value de "animal" contribui com 55 % do resultado. Os pesos do slide (0,05 / 0,55 / 0,10 / 0,10 / 0,20) são ilustrativos e não saem exatamente destas contas; aqui o softmax é calculado de verdade.

PLN IIFamílias de Transformers: encoder e decoder

Encoder: recebe o texto e constrói representações contextualizadas (entender). Decoder: usa o que tem disponível para produzir uma sequência de saída, em geral um token de cada vez (gerar).

FamíliaComo atuaUso típicoExemplo
Encoder-onlyAnalisa o contexto considerando as relações entre os tokensClassificação e compreensão textual, entidades, sentimentosBERT
Decoder-onlyProcessa o contexto disponível para prever o próximo token (atenção causal)Geração de texto, chatbots, códigoGPT
Encoder-decoderO encoder processa a entrada e o decoder produz a saídaTradução e transformação de textosT5

PLN IIPosição, múltiplas cabeças, bloco e máscara

Positional encoding

O Transformer não processa os tokens um por vez, então precisa de informação posicional somada à representação de cada token. Sem ela, "O cachorro perseguiu o gato" e "O gato perseguiu o cachorro" seriam indistinguíveis.

Multi-head attention

Vários mecanismos de atenção em paralelo, cada cabeça com suas próprias transformações de Q, K e V. Uma palavra se relaciona com as outras de várias formas ao mesmo tempo ("ele" precisa do referente, o verbo do sujeito, a vizinhança importa); uma única atenção obrigaria a fazer concessões. Os resultados das cabeças são combinados.

Bloco Transformer

  • Multi-Head Attention: relaciona informações entre os tokens.
  • Residual connection: soma a entrada original ao resultado da subcamada.
  • Layer normalization: estabiliza o processamento e o treinamento.
  • Feed-forward network: transformações adicionais nas representações.
  • Os blocos são empilhados para formar redes mais profundas.

Máscara causal

Em modelos que geram texto (GPT), o token não pode consultar tokens futuros. A máscara de atenção causal permite olhar só para trás, e isso viabiliza a geração autoregressiva.

Máscara causal

Linha = token que está sendo processado; coluna = token que ele pode consultar. ✅ permitido, ⛔ bloqueado.

PLN IILLMs: aprendizado e geração

Um LLM (Large Language Model) é um modelo treinado com grandes quantidades de texto para identificar padrões e relações na linguagem; tem milhões ou bilhões de parâmetros e consegue gerar, resumir, classificar e transformar textos. Muitos usam Transformers.

Como aprende

  • Pré-treinamento (pre-training): recebe enormes volumes de texto, aprende relações entre tokens e ajusta os parâmetros para melhorar suas previsões.
  • Fine-tuning: treinamento adicional para tarefas ou comportamentos específicos.
  • Instruction tuning: adaptação para seguir instruções do usuário.

Como gera uma resposta (autoregressiva)

  1. Recebe o prompt e faz a tokenização.
  2. Processa os tokens com a arquitetura Transformer.
  3. Calcula probabilidades para os possíveis próximos tokens.
  4. Seleciona um token, o adiciona à sequência e repete.

PLN IIRAG: Geração Aumentada por Recuperação

Um LLM só conhece o que viu no treinamento. Para responder com informações específicas (documentos internos, manuais, apostilas, bases atualizadas), usa-se RAG: o modelo consulta informações externas antes de responder.

FasePassos
1. Preparar a base de conhecimentoCarregar os documentos → dividir em trechos (chunks) → transformar cada trecho em embedding → guardar os vetores num banco de dados vetorial
2. Recuperar e gerarUsuário pergunta → pergunta vira embedding → busca dos trechos mais relevantes (vetores próximos) → trechos + pergunta vão ao LLM → o modelo responde usando esse contexto
Onde os embeddings entram

No RAG, os embeddings servem para a recuperação: o cosseno entre o vetor da pergunta e o dos chunks decide quais trechos chegam ao LLM.
